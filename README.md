# Larpgram Web — технический прототип

Отдельный локальный клиент. Канонический план: ../docs/WEB-PLAN.md.

## Запуск

Node >=22, `npm ci`, `npm run dev`. Открыть http://127.0.0.1:5173/.
`npm run build` — TypeScript и production-сборка; `npm test` — совместимость escrow.

Vite проксирует /account и /escrow на push.mango-kokos.ru, /_matrix на
matrix.mango-kokos.ru. Привязка dev-сервера только к loopback. Прокси нужны:
живой account preflight не возвращает Access-Control-Allow-Origin.
Для production нужно отдельно настроить эти same-origin маршруты либо узкий CORS.
Один dist без маршрутов API недостаточен.

## Реализовано в прототипе

Вход через account (включая код), Matrix password login, сохранение токена и device ID
в localStorage, Rust/WASM crypto в IndexedDB, Web Locks на одну вкладку.
Токен хранится на этом origin; пароль и ключ восстановления не сохраняются.
Escrow только читается: Argon2id v19, UTF-8, AES-GCM с user ID в AAD.
Ключ открывает secret storage, откуда SDK получает ключ backup; reset/bootstrap новых
ключей не вызываются. Ручной recovery key тоже поддерживается.
Чаты, последние 100 событий, текст и зашифрованные файлы, скачивание с проверкой хэша.
Выход через account/sessions/end с последующей очисткой локальных SDK stores.
Голосовые: запись (MediaRecorder, ogg/opus → webm/opus → mp4), отмена, предпрослушивание
с волной, лимит 5 минут, остановка при отключении микрофона, шифрованная отправка
m.audio с MSC3245 voice и MSC1767 audio (duration, waveform MSC3246 0..1024 — тот же
формат, что шлёт Android через Rust SDK). Входящие голосовые и аудио: волна и
длительность из msc1767, воспроизведение, скорость 1/1.5/2, скачивание.
Звонки: Element Call как React-компонент поверх нашего MatrixClient
(`src/Call.tsx`, ленивый чанк — основной бандл не раздувается). Сборка из
`../element-call-interface` @ 9f7c35c + interface.patch (`pnpm build:component`),
завендорена в `vendor/element-call-component` (пересборка: повторить build и
rsync component/dist). Шим `src/matrixrtc-shim.ts` добавляет
isLivekitTransportConfig (vite alias на matrix-js-sdk/lib/matrixrtc): компонент
собран против develop-снимка js-sdk 42.2.0, а у нас релиз 45.0.0 с новой
структурой транспортов. Кнопки Аудио/Видео в шапке чата, intent по
DM/группе и наличию активного звонка, индикатор «идёт звонок» в списке чатов.
Транспорт: well-known org.matrix.msc4143.rtc_foci → livekit-jwt-service на
matrix.mango-kokos.ru. Живая приёмка звонка веб ↔ Android ещё не выполнялась;
отдельно проверить CORS livekit-jwt-service из браузера (URL абсолютный,
не same-origin) и выдачу прав на камеру/микрофон.

## Следующая приёмка с владельцем

Вход, история, текст, файлы в обе стороны и голосовые веб ↔ Android приняты
владельцем 2026-11-02/03. Далее: двусторонний звонок веб ↔ Android (исходящий,
входящий, завершение, переподключение), push в фоне/закрытой вкладке,
федеративная переписка. SDK 45.0.0 выбран для исследования, совместимость с
Call ещё не подтверждена. Call не подключён, версия Android Call сохраняется
отдельно.

Пока отсутствуют: полноценный дизайн, звонки/push, пагинация,
персистентные черновики и очередь отправок, автоматическая передача вкладки,
регистрация/сброс пароля, подтверждение сессии/cross-signing UI.
При KDF >256 MiB выдаётся ошибка вместо выделения до 1 GiB на главном потоке;
перед пользовательским выпуском вынести Argon2 в worker и согласовать пределы.
При закрытой второй вкладке нужно вручную обновить страницу для захвата lock.
Голосовые: живая приёмка веб ↔ Android пройдена владельцем 2026-11-03
(запись в вебе, прослушивание на Android, входящие с Android в вебе).
Safari не декодирует ogg/opus: исходящая запись там уйдёт в
audio/mp4, а входящие ogg с Android в Safari могут не воспроизвестись — перед
выпуском решить (транскод на сервере или отдельный формат).
Личные аккаунты, backup и escrow не сбрасывать. Публикация не выполнялась.

Владелец вошёл через локальный UI и выполнил восстановление паролем.

тот же тестовый чат расшифровался без повторного пароля/восстановления.
Это подтверждает вход, восстановление backup и сохранность локальной криптобазы.
Скачивание файлов и новый двусторонний обмен с Android ещё не проверены.
Сообщения агент не отправлял; пароли/токены/содержимое переписки в отчёт не включены.

## Cross-signing веб-устройства — 2026-11-02

По сообщению владельца новый текст Android → веб и веб → Android доставлен.
Android помечает веб-отправителя как устройство, не проверенное владельцем.
Найден пропуск: recover загружал backup, но не импортировал существующую
cross-signing identity. Добавлен verifyOwnDevice: чтение трёх существующих
секретов подписи, importSecretsBundle, crossSignDevice только текущего device ID,
проверка signedByOwner и crossSigningVerified. При отсутствии секретов ошибка;
bootstrap/reset не вызываются. Сборка и 6 тестов прошли. Живая приёмка подписи пройдена владельцем (см. итог ниже).
Файловый обмен владелец пока отдельно не подтвердил.
