# Larpgram Web

Десктопный веб-клиент Larpgram. В общем checkout `element-fork` план выпуска и журнал приёмки находятся в соседнем каталоге `docs/`. [Источники иконок Android](ANDROID-ICONS.md).

## Запуск

Node >=22, `npm ci`, `npm run dev`. Открыть http://127.0.0.1:5173/.
`npm run build` — TypeScript и production-сборка; `npm test` проверяет escrow, cross-signing, голосовые и выбор режима звонка.

Vite проксирует /account и /escrow на push.mango-kokos.ru, /_matrix на
matrix.mango-kokos.ru. Привязка dev-сервера только к loopback. Прокси нужны:
живой account preflight не возвращает Access-Control-Allow-Origin.
Для production нужно отдельно настроить эти same-origin маршруты либо узкий CORS.
Один dist без маршрутов API недостаточен.

## Реализовано в клиенте

Вход через account (включая код), Matrix password login, сохранение токена и device ID
в localStorage, Rust/WASM crypto в IndexedDB, Web Locks на одну вкладку.
Токен хранится на этом origin; пароль и ключ восстановления не сохраняются.
После входа клиент использует введённый пароль для автоматического восстановления
истории и подтверждения нового веб-устройства. Если восстановление не удалось,
его можно повторить в настройках. При перезагрузке используются локальные ключи.
Восстановление читает escrow в формате Argon2id v19 и AES-GCM с user ID в AAD. При смене пароля из профиля существующий ключ перезапаковывается новым паролем. Серверный сценарий смены пароля и записи escrow остаётся на приёмку.
Ключ открывает secret storage, откуда SDK получает ключ backup; reset/bootstrap новых
ключей не вызываются. Ручной recovery key тоже поддерживается.
Чаты с догрузкой истории, локальными черновиками по комнатам, текстом и зашифрованными файлами. При скачивании проверяется хэш. В едином профиле доступны редактор, «Избранное» через Matrix account data и отдельные экраны настроек, в том числе аккаунт, уведомления и устройства.
Выход через account/sessions/end с последующей очисткой локальных SDK stores.

Папки Matrix находятся слева от списка чатов, архив открывается кнопкой рядом с «+».
В ленте есть отдельные дорожки для голосовых и музыки. Верхний плеер сохраняет
воспроизведение при смене чата и открывает очередь из загруженных треков исходной
комнаты. Плеер распознаёт FLAC в аудиособытиях и вложениях с расширением файла.
Нажатие на стикер открывает доступный набор по дескриптору события или по MXC.
В панели чата действия видны сразу, категории вложений прокручиваются по горизонтали.
Голосовые: запись (MediaRecorder, ogg/opus → webm/opus → mp4), отмена, предпрослушивание
с волной, лимит 5 минут, остановка при отключении микрофона, шифрованная отправка
m.audio с MSC3245 voice и MSC1767 audio (duration, waveform MSC3246 0..1024 — тот же
формат, что шлёт Android через Rust SDK). Входящие голосовые и аудио: волна и
длительность из msc1767, воспроизведение, скорость 1/1.5/2, скачивание.
Звонки: Element Call как React-компонент поверх нашего MatrixClient
(`src/Call.tsx`, ленивый чанк — основной бандл не раздувается). Сборка из
`../element-call-interface` @ 9f7c35c + interface.patch (`pnpm build:component`),
завендорена в `vendor/element-call-component` (пересборка: повторить build и
rsync component/dist). Шим `src/matrixrtc-shim.ts` добавляет
guard isLivekitTransportConfig и адаптирует joinRTCSession/leaveRoomSession к join/leave на той же сессии. Vite подставляет шим для matrix-js-sdk/lib/matrixrtc. Компонент
собран против develop-снимка js-sdk 42.2.0, а у нас релиз 45.0.0 с новой
структурой транспортов. Кнопки Аудио/Видео в шапке чата, intent по
DM/группе и наличию активного звонка, индикатор «идёт звонок» в списке чатов.
Транспорт: well-known org.matrix.msc4143.rtc_foci → livekit-jwt-service на
matrix.mango-kokos.ru. Preflight обоих JWT-маршрутов для локального Web прошёл. На рабочем Synapse включён MSC4075 для доставки Android-уведомлений о звонках.

## Приёмка перед выпуском

Владелец подтвердил входящий звонок Web → Android и обычные Android-уведомления.
При тестировании двух аккаунтов на одном телефоне Larpgram может отфильтровать
уведомление от второго аккаунта. Старая история в текущем Web-сеансе в целом читается.
На изолированных данных в Chromium проверены профиль, медиа, очередь музыки, архив
и панель вложений. Сборка и 14 тестов прошли.

Открыты восстановление в чистом профиле браузера на текущей сборке, серверные записи
профиля и аккаунта, «Избранное» на обеих платформах, звонок Android → Web, Web Push,
федерация и приёмка Edge/Safari. Для передачи Web Lock после закрытия активной вкладки
обновите ожидающую вкладку.

## Cross-signing веб-устройства — 2026-11-02

По сообщению владельца новый текст Android → веб и веб → Android доставлен.
Android помечает веб-отправителя как устройство, не проверенное владельцем.
Найден пропуск: recover загружал backup, но не импортировал существующую
cross-signing identity. Добавлен verifyOwnDevice: чтение трёх существующих
секретов подписи, importSecretsBundle, crossSignDevice только текущего device ID,
проверка signedByOwner и crossSigningVerified. При отсутствии секретов ошибка;
bootstrap/reset не вызываются. Сборка и 6 тестов прошли. Живая приёмка подписи пройдена владельцем (см. итог ниже).
Файловый обмен владелец пока отдельно не подтвердил.

### GIF в интерфейсе

В Vite маршрут `/gif-proxy` перенаправляется на существующий сервис
`https://gifs.mango-kokos.ru`. В окружении со статической сборкой нужен
тот же reverse proxy для `/gif-proxy/featured`, `/gif-proxy/search` и
`/gif-proxy/media`, со снятием префикса `/gif-proxy`. Скачанная GIF
проходит через обычный предпросмотр и отправку вложения Matrix.
